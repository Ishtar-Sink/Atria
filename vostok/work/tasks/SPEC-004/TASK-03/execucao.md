3. `apps/web/src/features/finance/lib/adjustments.ts` (criar), com um comentário no topo dizendo que a regra é a mesma de `apps/server/src/finance/domain/adjustment.rs` e que as contas usam `BigInt` porque o numerador do reverso passa de `Number.MAX_SAFE_INTEGER` (RNF-02):
   - Exporte `type AdjustmentDirection = 'deduction' | 'addition'`, `type AdjustmentMode = 'fixed' | 'percent'`, `interface Adjustment { name: string; direction: AdjustmentDirection; mode: AdjustmentMode; amount?: number | null; rate_bp?: number | null; base_amount?: number | null }`, `type ComputedAdjustment = Adjustment & { computed_amount: number }`, `interface Breakdown { gross_amount: number; net_amount: number; adjustments: ComputedAdjustment[] }`, `interface AdjustmentIssue { field: string; code: string }` e `type AdjustmentResult = { ok: true; breakdown: Breakdown } | { ok: false; issue: AdjustmentIssue }`.
   - Constantes `export const MAX_ADJUSTMENTS = 20;`, `export const ADJUSTMENT_NAME_MAX_CHARS = 60;`, `export const RATE_BP_MIN = 1;`, `export const RATE_BP_MAX = 9_999;` e `const BP_SCALE = 10_000n;`.
   - `function roundHalfUp(num: bigint, den: bigint): bigint` com `(2n * num + den) / (2n * den)` (num `>= 0`, den `> 0`); `function sign(direction: AdjustmentDirection): bigint` (−1n no desconto, 1n no acréscimo); `function fail(field: string, code: string): AdjustmentResult`; e `function toSafe(value: bigint): number | null` (`null` fora de `Number.MIN_SAFE_INTEGER..Number.MAX_SAFE_INTEGER`).
   - `export function validateAdjustments(items: readonly Adjustment[]): AdjustmentIssue | null`, na mesma ordem do servidor: mais de `MAX_ADJUSTMENTS` → `adjustments`/`too_many`; por item, nome aparado vazio → `adjustments.name`/`required` e com mais de 60 caracteres contados por ponto de código (`[...name.trim()].length`, como `chars()` no Rust) → `adjustments.name`/`too_long`; no `fixed`, `rate_bp` ou `base_amount` diferente de `null`/`undefined` → `adjustments.mode`/`fields_mismatch`, `amount` que não seja inteiro seguro `> 0` → `adjustments.amount`/`must_be_positive`; no `percent`, `amount` preenchido → `adjustments.mode`/`fields_mismatch`, `rate_bp` que não seja inteiro em `RATE_BP_MIN..RATE_BP_MAX` → `adjustments.rate_bp`/`out_of_range`, `base_amount` preenchido e `<= 0` → `adjustments.base_amount`/`must_be_positive`.
   - `function itemAmount(item: Adjustment, gross: bigint): bigint` (fixo: `BigInt(item.amount ?? 0)`; percentual: `roundHalfUp(BigInt(item.base_amount ?? gross) * BigInt(item.rate_bp ?? 0), BP_SCALE)`, com a base `bigint` quando vier do bruto) e `function breakdown(gross: bigint, items: readonly Adjustment[]): AdjustmentResult`, que calcula os `computed_amount`, o líquido `gross + Σ sign × computed_amount` e converte com `toSafe` (`null` → `adjustments`/`too_large`).
   - `export function computeNet(gross: number, items: readonly Adjustment[]): AdjustmentResult`: bruto que não seja inteiro seguro `> 0` → `gross_amount`/`must_be_positive`; `validateAdjustments`; `breakdown`; `net_amount <= 0` → `adjustments`/`net_not_positive`.
   - `export function grossForNet(net: number, items: readonly Adjustment[], expectedGross: number): AdjustmentResult`, igual ao `gross_for_net` do servidor: `net < 0` → `settled_amount`/`must_not_be_negative`; `expectedGross <= 0` → `expected_gross_amount`/`must_be_positive`; `validateAdjustments`; `fixedSum = Σ (−sign) × amount` dos fixos; `num = (net + fixedSum) × expectedGross × BP_SCALE`; `den = expectedGross × BP_SCALE + Σ sign × rate_bp × (base_amount ?? expectedGross)` dos percentuais; `den <= 0n` ou `num < 0n` → `adjustments`/`no_gross_for_net`; `gross = roundHalfUp(num, den)` (fora do inteiro seguro → `adjustments`/`too_large`); cada `base_amount` vira `roundHalfUp(base × gross, expectedGross)`, e zero → `no_gross_for_net`; `breakdown(gross, scaled)`; `residual = net − net_amount`; com `residual !== 0`, o último item `percent` da lista (laço `for` do fim para o começo; `findLastIndex` não está na `lib` ES2022 do `tsconfig.json`) recebe `computed_amount -= residual` no desconto ou `+= residual` no acréscimo (sem nenhum, ou valor negativo, → `no_gross_for_net`); `net_amount = net`.
   - Sem `any`, sem `@ts-ignore` e sem `Math.round` ou divisão de `number` no cálculo ([project/code-style-01], [project/code-style-05]).
